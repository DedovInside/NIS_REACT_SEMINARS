# Список пользователей - Practice 6

React-приложение для управления пользователями с использованием RTK Query и Axios.

## Функционал

### RTK Query

- **Просмотр списка пользователей** - GET запрос с автоматическим кэшированием
- **Добавление пользователя** - POST mutation с автоматическим обновлением списка
- **Редактирование пользователя** - PUT mutation с модальным окном

### Axios

- **Настроенные Interceptors**:
  - Автоматическое добавление `baseURL`
  - Автоматическое добавление токена `Authorization: Bearer demo-token`
- **AbortController** - отмена запросов через кнопку "Отменить загрузку"

## Технологии

- React 19 + TypeScript
- Redux Toolkit + RTK Query
- Axios с interceptors
- Vite

## API

Используется публичный REST API: `https://jsonplaceholder.typicode.com/`

- `GET /users` - получение списка пользователей
- `POST /users` - создание пользователя
- `PUT /users/:id` - обновление пользователя

## Особенности реализации

1. **Оптимистичное обновление RTK Query** - добавленные/изменённые пользователи сразу отображаются в списке без перезагрузки страницы ("оптимистичное" называется, потому что ожидаем успешный ответ, ведь это не настоящий API)
2. **Axios interceptors** - автоматически добавляют baseURL и Bearer токен ко всем запросам
3. **AbortController** - позволяет отменять Axios запросы (добавлена задержка 2 сек для демонстрации)
4. **Сброс кэша** - при загрузке через Axios сбрасывается кэш RTK Query, возвращаются оригинальные данные с сервера
5. **Тёмная тема** - современный дизайн в тёмных тонах
6. **Модальное окно** для редактирования пользователей (только оригинальных)
7. **Responsive design** для мобильных устройств

### Про оптимистичное обновление

JSONPlaceholder - это тестовый API, который **не сохраняет** данные реально. При использовании оптимистичного обновления:

- Новые/изменённые пользователи добавляются в локальный кэш RTK Query
- Они отображаются в UI как будто сохранены на сервере
- При нажатии "Загрузить через Axios" кэш сбрасывается, остаются только оригинальные 10 пользователей

На настоящем API можно было бы использовать пессимистичное обновление (`invalidatesTags`), и данные автоматически синхронизировались бы с сервером.
